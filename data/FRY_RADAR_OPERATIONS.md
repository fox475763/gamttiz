# GAMTTIZ FRY RADAR 운영·검증 기준

## 실행 일정
- GitHub Actions: `.github/workflows/fry-radar.yml`
- 한국 시간(KST) 00, 02, 04, 06, 08, 10, 12, 14, 16, 18, 20, 22시 정각 **예약**.
- GitHub Actions cron: `0 1-23/2 * * *` (UTC의 홀수 시간). GitHub의 작업 대기열 때문에 실제 시작 시점은 늦어지거나 드물게 누락될 수 있습니다.
- 워크플로의 `Run workflow` 버튼으로 수동 실행할 수 있습니다.

## 자동 수집 범위
1. Bing 뉴스 RSS: 감자튀김 할인·신제품·문화·굿즈와 프랜차이즈별 키워드.
2. Google 뉴스 RSS: 보조 검색. 원문 URL이 검증되지 않는 Google 리디렉션은 기사로 간주하지 않습니다.
3. 브랜드 공식 채널: 롯데리아, 맥도날드, 버거킹, 맘스터치, 프랭크버거, 노브랜드버거, 쉐이크쉑, 파이브가이즈, 다운타우너, 바스버거, KFC, 파파이스.
4. 브랜드 공식 페이지에서 직접 추출이 어려울 때 공식 URL만을 대상으로 검색 인덱스·브라우저 렌더링 보조 확인을 시도합니다.

**중요:** 위 목록은 확인을 시도하는 대상입니다. 모든 브랜드의 수집이 성공했다고 의미하지 않습니다. 일부 사이트는 로그인을 요구하거나, 봇 접근을 차단하거나, 동적 API가 비공개이므로 완전한 자동 수집을 보장할 수 없습니다.

## 정확성·데이터 보호
- 실제로 접근할 수 있는 원문 URL만 등록. 원문을 확보하지 못한 추측성 홍보·기사·행사기간은 만들지 않습니다.
- 과거 기사는 최근 14일 기준으로 구분하지만, 실제 종료일이 확인된 진행 중 행사는 오래된 기사여도 최근 목록에서 유지됩니다.
- 종료일이 확인되지 않은 기사에 '종료'를 추측해서 붙이지 않습니다.
- URL·제목·브랜드를 기준으로 중복을 제거하며 기존 소식은 수집 실패만으로 삭제하지 않습니다.
- `data/fry-radar-health.json`에는 최근 점검 시각, RSS 성공/실패, 공식 채널 접근 여부, 상세 후보와 확인 수, 제외 이유, 새 글 수가 기록됩니다.
- `tools/test-fry-radar.mjs`는 시간대, 날짜 해석, 원문 주소, 제목 중복, 관련성 규칙을 검증합니다.
- 매 실행의 결과는 GitHub Actions 로그에서 확인합니다. 기존 소식과 원문 사진은 유지하며, 외부 원본 사진을 재게시할 경우 이용 허락이 필요할 수 있습니다.

## 문제 진단
- 새 글 0건 + `reachable < sources`: **모든 소식을 확인한 것이 아닙니다.** 연결 실패 출처부터 확인해야 합니다.
- 목록 접근 0건: 해당 브랜드의 HTML 구조 또는 접근 정책이 변경된 것일 수 있습니다.
- RSS 후보 다수 + 등록 0건: 대부분 무관하거나 기준 미충족일 수 있으며, 원문 확인·기간·중복 조건을 점검해야 합니다.
- GitHub Actions 실패: 워크플로의 `collect` 작업에서 오류 로그를 확인하세요. 게시 데이터의 자동 삭제나 강제 덮어쓰기를 하지 않도록 구성돼 있습니다.
